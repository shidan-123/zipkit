## 1. 先装 Python

ZipKit 是一个 Python 程序，所以机器上要有 **Python 3.9 或更新**。

### 检查

打开"终端"（Windows 叫 PowerShell / 命令提示符，macOS 用"终端"，Linux 用任意 shell），输入：

```bash
python3 --version      # macOS / Linux
python --version       # Windows
```

期望看到 `Python 3.9.x` 或更高。

### 没有或版本太低

| 系统 | 做法 |
|---|---|
| Windows | 打开 <https://www.python.org/downloads/>，下载最新版，安装时**务必勾选 `Add Python to PATH`**，装完重开终端 |
| macOS | 推荐 `brew install python`；也可以从 python.org 下载 pkg 双击安装 |
| Linux (Debian/Ubuntu) | `sudo apt update && sudo apt install -y python3 python3-pip` |
| Linux (Fedora) | `sudo dnf install -y python3 python3-pip` |

> Windows 上如果 `python` 没反应，试试 `py --version`，后面命令里的 `python3` 都换成 `py`。

## 2. 网页版：三步搞定

适合：不熟悉命令行、只是偶尔压一下文件、想看清楚每个文件省了多少。

### 第 1 步：拿到代码

```bash
git clone https://github.com/shidan-123/zipkit.git
cd zipkit
```

没有 git？在 GitHub 页面点 **Code → Download ZIP**，解压后进入目录。

### 第 2 步：启动

```bash
python3 -m zipkit web
```

终端会打印：

```text
  ╭──────────────────────────────────────────────╮
  │  ZipKit 网页版已启动，在浏览器里操作即可      │
  ╰──────────────────────────────────────────────╯

  地址：http://127.0.0.1:8765/?token=xxxxxxxxxxxxxxxx
  只监听：127.0.0.1（外部机器无法访问）
  上传上限：64 MB

  关掉服务：在这个终端窗口按 Ctrl + C
```

浏览器一般会自动打开。**没自动打开就手动复制那行地址**（注意 `?token=` 后面那一串必须带着，否则页面会被拒绝）。

### 第 3 步：用

界面上有三个标签页：

#### 压缩

1. 把 `.txt / .log / .csv / .json / .bmp / .wav / .tiff` 拖进虚线框（可多选）
2. 选压缩级别：
   - **平衡**（默认）—— 速度和体积都还行，日常用它
   - **快** —— 赶时间，文件会大一点
   - **最小** —— 多花几秒换更小的包
3. 点 **开始压缩**
4. 看结果表：每个文件的原始大小 / 压缩后 / 节省百分比
5. 点 **下载** 拿到 zip

> 如果看到"几乎压不动"的黄条，不是出错——那是 BMP/WAV/TIFF 本身太"密"。

#### 解压

1. 拖入 `.zip / .7z / .gz / .tar.gz / .tgz / .tar / .docx / .xlsx / .pptx`
2. 点 **开始解压**
3. 浏览器只能下载单个文件，所以 ZipKit 会把解压结果**再打成一个 zip** 给你下载
4. 下载后自己再解一次，就能看到文件

#### 读文档

1. 拖入 `.docx / .xlsx / .pptx`
2. 点 **提取文字**
3. 文字出现在下方文本框里，可以 **复制全部**
4. 想改内容 → 用 Office / WPS 打开**原文件**改，不要改解包出来的 XML

### 关掉

在启动服务的那个终端窗口按 `Ctrl + C`。页面会失效，但已下载的文件不受影响。

## 3. 命令行版：五个命令

适合：文件很大（网页版上限 64 MB）、要批量处理、想写进脚本。

先进入项目目录：

```bash
cd zipkit
```

### `pack` —— 压缩

```bash
python3 -m zipkit pack <文件或目录...> [-o 输出.zip] [-l 级别]
```

| 参数 | 说明 | 默认 |
|---|---|---|
| `文件或目录` | 可以给多个；给目录会递归打包 | 必填 |
| `-o, --output` | 输出 zip 路径 | `zipkit-时间戳.zip` |
| `-l, --level` | `fast` / `balanced` / `max` | `balanced` |
| `--json` | 输出 JSON，给脚本用 | 关 |

例子：

```bash
# 单个文件
python3 -m zipkit pack 会议纪要.txt

# 多个文件
python3 -m zipkit pack 报告.txt 数据.csv 截图.bmp -o 本周资料.zip

# 整个目录（保留目录结构）
python3 -m zipkit pack ./logs -o logs-2026-10.zip -l max
```

### `unpack` —— 解压

```bash
python3 -m zipkit unpack <压缩包> [-d 目标目录] [-f] [--max-total MB] ...
```

| 参数 | 说明 | 默认 |
|---|---|---|
| `压缩包` | `.zip/.7z/.gz/.tar.gz/.tgz/.tar/.docx/.xlsx/.pptx` | 必填 |
| `-d, --dest` | 解压到哪 | `<文件名>_extracted` |
| `-f, --force` | 同名文件直接覆盖 | 关（自动改名） |
| `--max-total` | 解压总量上限（MB） | 2048 |
| `--max-single` | 单文件上限（MB） | 1024 |
| `--max-files` | 文件个数上限 | 20000 |
| `--max-ratio` | 压缩比上限（防炸弹） | 200 |

例子：

```bash
python3 -m zipkit unpack 资料.zip                # 解到 资料_extracted/
python3 -m zipkit unpack 资料.zip -d ./解压结果    # 指定目录
python3 -m zipkit unpack 大包.zip --max-total 8000 # 明确信任这个包
```

### `list` —— 看里面有什么（不解压）

```bash
python3 -m zipkit list 资料.zip
```

输出每个成员的原始大小和压缩后大小。**下载了不明压缩包时，先 `list` 再决定要不要解。**

### `text` —— 抽 Word/Excel/PPT 的文字

```bash
python3 -m zipkit text 报告.docx            # 打印到屏幕
python3 -m zipkit text 报告.docx -o 报告.txt  # 存成文本文件
```

### `check` —— 压缩前体检

```bash
python3 -m zipkit check *.wav *.bmp *.log
```

它会告诉你：类型、大小、这类格式"通常能压多少"、以及**按实际内容估算**的压缩率。

> 看到 `预估可压缩：█░░░░░░░░░░░ 6%` 就别折腾了，压了也就省几 KB。

### 附加：`web`

```bash
python3 -m zipkit web --port 9000 --no-browser
```

| 参数 | 说明 |
|---|---|
| `--port` | 端口，默认 8765；被占用会自动往后找 |
| `--host` | 默认 `127.0.0.1`（只本机）。**不要随便改成 0.0.0.0**，那等于把工具暴露给局域网 |
| `--no-browser` | 不自动开浏览器 |
| `--max-upload` | 上传上限 MB，默认 64 |

## 4. 四个典型场景

### 场景 A：日志太大，想归档

```bash
python3 -m zipkit check ./logs/*.log        # 先看值不值
python3 -m zipkit pack ./logs -o logs-2026-10.zip -l max
```

日志通常能压 90%+，放心压。

### 场景 B：给同事发一堆文件

```bash
python3 -m zipkit pack 报告.docx 数据.xlsx 附图/ -o 发给李工的资料.zip
```

注意：`.docx/.xlsx` 本身压不掉多少（6%~20%），主要目的是"打包成一个文件"。

### 场景 C：微信里收到的 7z 打不开

```bash
pip install py7zr                 # 只有第一次需要
python3 -m zipkit list 收到的.7z   # 先看看里面是啥
python3 -m zipkit unpack 收到的.7z
```

### 场景 D：只想从 Word 里复制文字发微信

```bash
python3 -m zipkit text 通知.docx
```

或者网页版 → **读文档** → 拖进去 → **复制全部**。

## 5. 格式速查表

| 你手里的文件 | 该用哪个命令 | 预期结果 |
|---|---|---|
| `.txt .log .csv .json` | `pack` | 大幅变小（70%~95%） |
| `.bmp .wav .tiff` | `pack` | 小幅度变小（5%~30%），**属正常** |
| `.zip .7z .gz .tar.gz` | `unpack` | 解出文件 |
| `.docx .xlsx .pptx` | `text` | 得到纯文字 |
| `.docx .xlsx .pptx` | `unpack` | 得到 XML 结构（研究用，不推荐日常） |
| `.rar` | ❌ 不支持 | 先用官方 WinRAR / 7-Zip 转成 zip |
| `.jpg .mp4 .mp3` | ❌ 不建议压 | 已经压缩过，ZIP 压不动 |

## 6. 几条必须知道的规矩

### ① 不要"解压 docx 再压回去"

Word 文档内部有校验和与关系文件，手工解包 → 改 XML → 重新压缩，**极大概率打不开**。改内容请用 Office/WPS。

### ② 默认不会覆盖你的文件

解压时遇到同名文件，会自动变成 `报告 (1).txt`。只有你明确加 `-f` 才会覆盖。

### ③ 网页版有大小上限

默认 64 MB。大文件走命令行——命令行没有这个上限（受磁盘空间限制）。

### ④ 中文路径没问题，但终端可能显示乱码

- Windows PowerShell 遇到中文乱码：先执行 `chcp 65001`
- 文件名本身不受影响，只是显示问题

### ⑤ 你的文件不会离开你的电脑

网页版跑在 `127.0.0.1`，只监听本机，没有任何联网请求。可以断网使用。
