# 使用限制（试用前必读）

> 这份文档只讲一件事：**哪些情况下 ZipKit 会"做不到"或"被拦住"**。
> 提前知道，能省掉 90% 的"以为坏了"。
> 报错看不懂时对照 [故障排查](故障排查.md)。

---

## 一、一页速查表

| 限制 | 默认值 | 能不能改 | 怎么改 |
|---|---|---|---|
| 网页版单次上传 | **64 MB** | ✅ | `python3 -m zipkit web --max-upload 512` |
| 解压文件个数 | 20,000 | ✅ | `--max-files 50000` |
| 解压后总量 | 2 GB | ✅ | `--max-total 8000`（单位 MB） |
| 单个文件 | 1 GB | ✅ | `--max-single 4000` |
| 压缩比（防炸弹） | 200:1 | ✅ | `--max-ratio 5000` |
| 监听地址 | 仅 `127.0.0.1` | ⚠️ 不建议改 | `--host 0.0.0.0`（等于开放给局域网） |
| 支持解压 `.rar` | ❌ 不支持 | ❌ | 先用其他工具转 `.zip` |
| 支持加密压缩包 | ❌ 不支持 | ❌ | v1.1 计划 |
| 支持 `.7z` | ⚠️ 需装库 | ✅ | `pip install py7zr` |
| 微信小程序版 | ❌ 没有 | ❌ | 见 [小程序方案](小程序方案.md) |

## 二、网页版的限制

### ① 单次上传 64 MB —— 你刚才撞到的就是这个

**原因**：浏览器只能把文件内容塞进请求里，ZipKit 用 Base64 编码传输，
会额外膨胀 **33%**。351 MB 的文件传上去约 468 MB，还要在内存里同时存在多份。

**表现**：

```text
请求太大（上限 64.0 MB）
压缩/解压大文件请用命令行
```

**怎么办**（四选一）：

```bash
# ① 桌面窗口版：双击启动，无大小限制（最适合新手）
#    macOS 双击「启动-ZipKit大文件版.command」
#    Windows 双击「启动-ZipKit大文件版.bat」
python3 -m zipkit gui

# ② 命令行（没有限制，适合脚本）
python3 -m zipkit unpack 大文件.zip

# ③ 临时把网页版上限调高（注意内存占用，352 MB 会吃约 1.5 GB）
python3 -m zipkit web --max-upload 512

# ④ 先拆分再传（其实命令行更省事）
```

> **经验值**：文件超过 100 MB 就别用网页版了，改用**桌面窗口版**或命令行——它们直接读写硬盘，不经过内存中转。

### ② 只能本机访问

网页版默认只监听 `127.0.0.1`，**同一 WiFi 下的手机、别的电脑都连不上**。

这是刻意的：它是个"本机工具"，不是"网络服务"。
如果你确实要给别人用（比如放在局域网服务器上），需要自己加鉴权、HTTPS、限流——那是另一件事。

### ③ 解压结果要再下一次

浏览器不能"把文件夹写到你的下载目录"，所以 ZipKit 把解压结果**再打成一个 zip** 给你。
你要多解一次才能看到文件。命令行没有这个问题。

### ④ 每次启动 token 都变

刷新旧标签页会报 `请求缺少有效令牌`。必须用终端里最新打印的那个地址。

## 三、格式限制

### ① 不支持 `.rar`（也不打算支持）

RAR 是专有格式，Python 生态里没有可靠的开源实现。

```bash
# 先用系统工具转成 zip
# macOS：只能装第三方（如 Keka）；Linux：unrar 免费但非自由软件；Windows：WinRAR / 7-Zip
```

### ② 不支持加密压缩包（v1.1 计划）

```text
这个 ZIP 加了密码，无法解压
```

先用系统工具解（macOS 归档实用工具会弹密码框、Windows 用 7-Zip、Linux `unzip -P 密码`）。

### ③ `.7z` 需要额外装库

```bash
pip install py7zr
```

装不上（公司网络/离线）就先用 7-Zip 官方软件。

### ④ `.gz` 只能装一个文件

`.gz` 是**单文件压缩流**，不是归档。看到"解压出来只有一个文件"是正常的。
装了多个文件的是 `.tar.gz`（ZipKit 也支持）。

### ⑤ `.docx/.xlsx/.pptx` "解压"出来是 XML

它们的本质是 ZIP 容器。解开会得到 `word/document.xml` 这类文件：

- **不能**直接编辑后压回去（大概率打不开）
- 想读文字 → 用 `zipkit text 文件.docx`
- 想改内容 → 用 Office / WPS 打开原文件

### ⑥ `.bmp/.wav/.tiff` 压缩收益很低

| 格式 | 实测收益 | 为什么 |
|---|---|---|
| `.bmp` | 5%~15% | 未压缩像素点阵，ZIP 榨不出多少 |
| `.tiff` | 0%~10% | 常常本身已是 LZW |
| `.wav` | 10%~40% | PCM 波形；合成音可能很高，真实录音不会 |

真正有效的替代：**BMP→PNG、TIFF→PNG、WAV→FLAC**（能小 5~10 倍）。
压缩前先跑 `python3 -m zipkit check 文件`，它会告诉你值不值得。

### ⑦ `.jpg/.png/.mp4/.mp3/.zip/.7z` 再压几乎无意义

这些格式已经压缩过。ZipKit 不禁止你压，但别期待变小。

## 四、安全限制（可能"误伤"正常文件）

这些闸门是为了防恶意压缩包，但**极端数据也可能被拦**：

| 闸门 | 什么时候会误伤 | 怎么放宽 |
|---|---|---|
| 压缩比 > 200:1 | 全零日志、磁盘镜像、数据库导出 | `--max-ratio 5000` |
| 解压总量 > 2 GB | 大型数据集、游戏资源包 | `--max-total 20000` |
| 单文件 > 1 GB | 视频、虚拟机镜像 | `--max-single 5000` |
| 成员数 > 20000 | `node_modules`、源码发布包 | `--max-files 200000` |

**判断标准**：如果这个包是**你自己打包的**或来自**可信来源**，放宽是安全的。
来自陌生人/网盘的包，先 `zipkit list` 看一眼再决定。

### 会被直接拒绝的（不建议放宽）

| 成员名特征 | 例子 | 原因 |
|---|---|---|
| 含 `..` | `../../.ssh/authorized_keys` | 路径穿越攻击 |
| 绝对路径 | `/etc/passwd`、`C:\Windows\...` | 写到系统目录 |
| 控制字符 | `报告.txt\x00.exe` | 伪造扩展名 |
| Windows 设备名 | `CON`、`NUL`、`COM1` | 在 Windows 上行为异常 |

遇到这些**不要解**，直接删。

## 五、性能与资源

| 场景 | 表现 | 建议 |
|---|---|---|
| 1 GB 文本压缩 | 约 10~30 秒（取决于 CPU） | 可接受 |
| 1 GB 视频压缩 | 约 5~10 秒，但**只省 1%** | 别压 |
| 解压 10 万个小文件 | 慢（每个文件都要建目录项） | 用命令行，别用网页 |
| 网页版 64 MB | 内存峰值约 250 MB | 正常 |
| 网页版 500 MB | 内存峰值约 2 GB | **会卡**，改用命令行 |

**磁盘空间**：解压需要目标大小的 1 倍空间。解压前确认磁盘够。

## 六、平台差异

| 平台 | 需要注意 |
|---|---|
| **Windows** | 终端中文乱码 → 先执行 `chcp 65001`；路径长度 > 260 字符会失败（系统限制）；用 `python` 而不是 `python3` |
| **macOS** | 系统自带 Python 是 3.9（够用）；`pip install` 建议加 `--user` 或建 venv；解压到 `~/Documents` 可能触发权限弹窗 |
| **Linux** | 需要 `python3-venv` 才能建虚拟环境；无 `tkinter` 也能用（本项目不依赖 GUI 库） |

## 七、这些不是 ZipKit 的限制（别怪它）

| 现象 | 真实原因 |
|---|---|
| 解压出来的 `.exe` 双击打不开 | macOS/Linux 不能运行 Windows 程序，需要虚拟机 |
| 解压出来的 `.exe` 提示"已损坏" | macOS 的安全隔离（Gatekeeper），跟压缩包无关 |
| Office 文档解包改完打不开 | 你破坏了 OOXML 的内部关系表，不是工具的问题 |
| 扫描件提取不出文字 | 图片里的字需要 OCR，ZipKit 不做 OCR |
| 视频压完还是那么大 | 视频早已压缩，信息论决定它压不动 |
| 解压后文件名乱码 | 老式 ZIP 编码问题；ZipKit v1.0.1 已自动修复 GBK 乱码，仍不行的用 7-Zip 手动指定编码 |

## 八、微信小程序版本

**v1.0 没有，v2.0 才计划。** 原因不是懒：

- 主包 ≤ 2 MB，装不下 7z 的 WASM 库
- 小程序没有本地进程，不能调系统解压
- 文件只能从聊天记录选，拖不了大文件

要做必须有服务器 + 备案域名，成本见 [小程序方案](小程序方案.md)。

## 九、试用建议（按这个顺序，少踩坑）

```bash
# 1. 先确认能跑起来
python3 -m zipkit --version

# 2. 用官方样例试，不碰你的真实文件
python3 scripts/make_demo.py demo
python3 -m zipkit pack demo -o 测试.zip
python3 -m zipkit unpack 测试.zip -d 测试输出

# 3. 再拿你自己的真实文件试（先看，不解）
python3 -m zipkit check 你的文件.*
python3 -m zipkit list 你的压缩包.zip

# 4. 最后才真解压，且解到新目录
python3 -m zipkit unpack 你的压缩包.zip -d 新目录名
```

**三条铁律**：

1. 不确定的包，先 `list` 再 `unpack`
2. 永远解到新目录（用 `-d` 指定），别解到桌面
3. 大文件（> 100 MB）别用网页版
