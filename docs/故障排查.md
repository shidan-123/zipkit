# 故障排查与补救

> 先找到你屏幕上那句话，再往下翻。
> 每条都按「**现象 → 原因 → 怎么办**」写。

---

## 一、启动类问题

### `python3: command not found` / `python 不是内部或外部命令`

**原因**：没装 Python，或装了但没加进 PATH。

**怎么办**：

| 系统 | 操作 |
|---|---|
| Windows | 重装 Python，安装第一屏**勾选 `Add Python to PATH`**；或临时用 `py` 代替 `python` |
| macOS | `brew install python`；没有 brew 就去 python.org 下 pkg |
| Linux | `sudo apt install python3`（Debian/Ubuntu）/ `sudo dnf install python3`（Fedora） |

### 双击 App 时 `PermissionError: [Errno 1] Operation not permitted`

**原因**：macOS 隐私保护（TCC）。从 Finder 启动的 App 默认**不能读取**
`~/Downloads`、`~/Documents`、`~/Desktop`、`~/Desktop` 这些"受保护文件夹"。
项目放在这些位置时，Python 连自己的代码都读不到。

**表现**：弹窗说"Python 加载程序失败"，日志里是 `_path_importer_cache` → `PermissionError`。

**怎么办**（二选一）：

1. **用 v1.1.3 及以后的 `ZipKit.app`**：代码已复制进应用内部，读取自身不受限制（推荐）
2. 把整个项目移到不受保护的位置，例如 `~/zipkit`（家目录根下不受 TCC 保护）：

```bash
mv ~/Downloads/DeepSeek/zipkit ~/zipkit
open ~/zipkit
```

> 注意：`~/Documents`、`~/Desktop`、`~/Downloads` 都属于受保护目录，换过去同样会失败。

### `No module named zipkit`

**原因**（两种）：

1. 不在项目根目录下执行，或项目文件夹没下载完整；
2. **双击 `ZipKit.app` 时**：启动器依赖"当前目录"来导入，而 Finder/launchd 启动时
   `sys.path` 可能不含 CWD（`PYTHONSAFEPATH` 等设置会触发）。

**怎么办**：

- v1.1.2 起，`ZipKit.app` 会显式设置 `PYTHONPATH` 并先自检，正常不会再出现；
  若仍出现，直接看 `~/Library/Logs/ZipKit.log`，里面记录了 `PATH` / `PYTHONPATH`。

- 命令行方式依旧可以手动指定：

```bash
cd /路径/to/zipkit
PYTHONPATH="$PWD" python3 -m zipkit gui
```


```bash
cd /路径/to/zipkit      # 必须能看到 zipkit/ 和 pyproject.toml
ls                       # 确认里面有 zipkit、tests、README.md
python3 -m zipkit --version
```

### `SyntaxError` 开头的报错

**原因**：Python 版本低于 3.9。

**怎么办**：`python3 --version` 确认；升级 Python 即可。本项目刻意不用 3.10+ 的语法。

### `Address already in use` / 端口被占用

**原因**：上次的 ZipKit 没关，或 8765 被别的程序占了。

**怎么办**：

```bash
python3 -m zipkit web --port 9000
```

ZipKit 本身也会自动往后找可用端口（8765→8784）。

## 二、网页版问题

### 浏览器打开是空白 / `{"error": "请求缺少有效令牌"}`

**原因**：直接用 `http://127.0.0.1:8765/` 打开了，没带 `?token=`。

**怎么办**：回到终端，复制**完整**那行地址（含 `?token=...`）。每次重启服务 token 都会变，旧的收藏夹链接会失效。

### 页面能打开，但点"开始压缩"报 403

**原因**：同上，token 不对或页面是旧标签。

**怎么办**：关掉旧标签，用终端里最新地址重新打开。

### 点下载没反应

**原因**：浏览器拦截了多文件下载，或弹窗被拦。

**怎么办**：看地址栏右侧有没有"已阻止下载"图标，点允许；或者改用命令行。

### 上传大文件报 `请求太大`

**原因**：超过 64 MB 默认上限（Base64 还会放大 33%）。

**怎么办**：大文件用命令行：

```bash
python3 -m zipkit pack 大文件.bmp -o 大文件.zip
```

## 三、压缩类问题

### 压完几乎没变小

**这是正常现象**，不是 bug。原因：

| 格式 | 为什么压不动 |
|---|---|
| `.bmp` | 原始位图，ZIP 能压进一点，但 PNG 会小 5~10 倍 |
| `.wav` | PCM 波形数据，FLAC 才是正解 |
| `.tiff` | 常常本身已是 LZW |
| `.docx/.xlsx/.pptx` | 内部已 DEFLATE 压缩过 |
| `.jpg/.png/.mp4/.mp3` | 已经是有损/无损压缩格式 |

**怎么办**：`python3 -m zipkit check 文件` 先看预估收益，低于 10% 就别压了。

### `找不到这个文件或目录`

**原因**：路径拼错；或路径里有空格没加引号。

**怎么办**：

```bash
python3 -m zipkit pack "我的 文件.txt"     # 有空格要加引号
```

Windows 反斜杠路径也支持：`python3 -m zipkit pack "C:\Users\你\Desktop\a.txt"`

### 压缩结果里多了一层目录名

**原因**：给的是目录，ZipKit 会以目录名作为顶层（避免解压时几百个文件散落）。

**怎么办**：这是刻意设计。想要"扁平"结构，就逐个文件传：

```bash
python3 -m zipkit pack demo/*.txt -o 只有文本.zip
```

## 四、解压类问题

### `不认识这个格式`

**原因**：文件被改过扩展名，或根本不是压缩包；`.rar` 也不支持。

**怎么办**：

```bash
python3 -m zipkit check 这个文件      # 看它实际是什么
```

不支持 `.rar`：先用 WinRAR / 7-Zip / macOS 的 Keka 转成 `.zip`。

### `ZIP 结构损坏`

**原因**：下载不完整（最常见）、传输被截断、存储介质出错。

**怎么办**：

1. 重新下载一次（对比文件大小）
2. 用系统自带工具验证：macOS 双击、Windows 右键"全部解压缩"、Linux `unzip -t 文件.zip`
3. 都不行 → 源头文件本身就坏了，找发件人重发

### `这个 ZIP 加了密码，无法解压`

**原因**：加密压缩包。

**怎么办**：目前 ZipKit 不支持密码。用系统工具（macOS 归档实用工具、Windows 7-Zip、Linux `unzip -P 密码`）先解。加密支持在 v1.1 计划里。

### `压缩比高达 1234:1，疑似压缩炸弹`

**原因**：ZipKit 的安全闸门（默认 200:1）拦住了。可能是真炸弹，也可能是"正常但极度重复"的数据（比如全零的磁盘镜像）。

**怎么办**：确认来源可信后再放宽：

```bash
python3 -m zipkit unpack 这个包.zip --max-ratio 5000 --max-total 20000
```

### `拒绝跳目录的成员：../xxx` / `拒绝绝对路径成员`

**原因**：这是**恶意压缩包**的典型特征（ZIP 路径穿越攻击），ZipKit 主动拦住了。

**怎么办**：**别解开**。删掉它，或让发件人用正常工具重新打包。如果你确信是误报，用系统工具在沙箱/虚拟机里解，不要在主目录解。

### `解压 .7z 需要额外安装一个纯 Python 库`

```bash
pip install py7zr
```

装不上（比如公司网络）就先用 7-Zip 官方软件解。

### 解压后在 Windows 上文件名是乱码

**原因**：ZIP 的编码标记问题（老版本 Windows 压缩工具常见）。

**怎么办**：在 Windows 上用 7-Zip 打开，它支持手动指定编码（GBK）。ZipKit 优先按 UTF-8 解码，遇到无标记的老包可能不准。

## 五、Office 文档问题

### `这个 Office 文件已损坏（不是合法 ZIP）`

**原因**：

- 其实是老格式 `.doc/.xls/.ppt`，只是被改了扩展名
- 文件下载中断
- 被邮件网关/网盘处理过

**怎么办**：用 Office/WPS 打开 → 另存为 `.docx/.xlsx/.pptx` → 再试。

### 提取出来的文字是空的

**原因**：

- `.xlsx` 只有图表/图片，没有单元格文字
- `.pptx` 文字在图片里（扫描件）
- 文档用了特殊字体/嵌入对象

**怎么办**：用原软件打开确认内容形态；扫描件需要 OCR，不在本项目范围。

## 六、文件被覆盖了，怎么救

这是最需要冷静的环节。**第一原则：立刻停止往那个磁盘写入。**

### 情况 1：你用了 `-f/--force` 覆盖

**还能救吗**：如果原来的文件也是从某个 zip 解出来的，**原始 zip 还在** → 直接重新解压到新目录。

```bash
python3 -m zipkit unpack 原始包.zip -d 恢复目录
```

### 情况 2：默认行为下文件名变成 `xxx (1).txt`

**没有丢**：原文件还在，新的加了序号。两个都在目录里，看清楚再删。

### 情况 3：真的误删了

按成功率从高到低：

1. **回收站 / 废纸篓** —— Windows 和 macOS 删除的文件先在这里
2. **Time Machine**（macOS）—— 进入 Time Machine 找那个时间点
3. **文件历史记录**（Windows）—— 控制面板 → 文件历史记录
4. **云同步版本** —— OneDrive / iCloud / 坚果云 一般保留 30 天历史版本
5. **专业恢复工具** —— `PhotoRec`、`Recuva`，越早越好，且**恢复到另一块磁盘**

⚠️ 覆盖写过的文件，靠软件恢复的成功率很低。这也是为什么 ZipKit 默认**不覆盖**。

### 预防：把这条当成规矩

- 重要文件先 `git init` 或用 Git LFS 管起来
- 解压永远解到**新目录**（`-d` 指定一个没用的名字）
- 养成 `list` 一下再 `unpack` 的习惯

## 七、报 Bug 前请提供这些

去 <https://github.com/shidan-123/zipkit/issues> 新建 Issue 时，附上：

1. **操作系统和 Python 版本**：`python3 --version` + 系统版本
2. **完整命令**：你敲的那行，原样复制
3. **完整报错**：从 `❌` 开头那行到最后一行
4. **文件特征**：类型、大小（**不要上传包含隐私的文件**；能复现就行）
5. **是否可复现**：每次都能复现，还是偶然一次

有这五项，大部分问题能在一轮内定位。

## 八、错误信息对照速查

| 你看到的 | 一句话原因 | 一句话解决 |
|---|---|---|
| `command not found` | 没装/没进 PATH | 重装并勾 PATH |
| `No module named zipkit` | 不在项目根目录 | `cd` 进去 |
| `找不到这个文件或目录` | 路径错/空格没引号 | 加引号，用 `ls` 确认 |
| `不认识这个格式` | 不是压缩包 / .rar | `check` 看类型，先转换 |
| `ZIP 结构损坏` | 下载不完整 | 重新下载 |
| `加了密码` | 加密包 | 系统工具解，等 v1.1 |
| `疑似压缩炸弹` | 安全闸门 | 确认可信后调 `--max-ratio` |
| `拒绝跳目录的成员` | 恶意包特征 | 别解，直接删 |
| `需要 py7zr` | 缺可选依赖 | `pip install py7zr` |
| `已损坏（不是合法 ZIP）` | 老版 Office 格式 | 另存为新格式 |
| `超过单文件上限` | 安全闸门 | 调 `--max-single` |
| `请求缺少有效令牌` | 没带 ?token= | 用终端里的完整地址 |
